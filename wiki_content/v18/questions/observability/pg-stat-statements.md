# How pg_stat_statements Works and Which Settings Affect It in PostgreSQL 18 (unverified)

## Question

> Follow AGENTS.md.
> In PostgreSQL 18, explain how `pg_stat_statements` works and give a comprehensive explanation of all configuration settings that affect `pg_stat_statements`.

## Short Answer

`pg_stat_statements` is a shared-preload extension that records planning time, execution time, row counts, buffer usage, WAL generation, JIT counters, and parallel-worker counters for normalized statement identities across the whole server cluster [pg_stat_statements.c#header](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L3-L20) [pgstatstatements.sgml#intro](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L10-L37). The SQL objects are installed per database with `CREATE EXTENSION pg_stat_statements`, but the collected statistics span all databases because the extension's state is in shared memory [pgstatstatements.sgml#intro](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L27-L37).

The core requirements are `shared_preload_libraries = 'pg_stat_statements'` and a nonzero query identifier. `_PG_init()` returns without installing hooks unless the module is being loaded during `shared_preload_libraries`, then calls `EnableQueryId()`, defines the extension GUCs, and installs parser, planner, executor, utility, shared-memory request, and shared-memory startup hooks [pg_stat_statements.c#_PG_init](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L381-L488). `pgss_store()` refuses to store a statement whose `queryId` is zero, so `compute_query_id = off` or a missing third-party query-ID provider disables collection for statements that reach the extension with no identifier [pg_stat_statements.c#pgss_store](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1281-L1309).

There are five direct `pg_stat_statements.*` settings: `max`, `track`, `track_utility`, `track_planning`, and `save` [pg_stat_statements.c#custom-GUCs](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L407-L463). Other PostgreSQL settings that directly affect visible `pg_stat_statements` output are `shared_preload_libraries`, `compute_query_id`, `track_io_timing`, JIT settings, and parallel-query settings; ordinary planner and workload settings can also change the observed numbers indirectly by changing plans, execution paths, row counts, I/O, WAL, or JIT use.

## How Collection Works

PostgreSQL computes query IDs at parse-analysis time when `IsQueryIdEnabled()` is true. The in-core "query jumble" hashes selected parse-tree fields, ignores nonessential fields such as constant values, and stores the 64-bit result in `Query.queryId` [queryjumblefuncs.c#overview](../../../../raw/postgres-18/src/backend/nodes/queryjumblefuncs.c#L1-L27) [analyze.c#parse-analysis-query-id](../../../../raw/postgres-18/src/backend/parser/analyze.c#L122-L132) [queryjumblefuncs.c#JumbleQuery](../../../../raw/postgres-18/src/backend/nodes/queryjumblefuncs.c#L131-L158). `compute_query_id = auto` lets a module such as `pg_stat_statements` request query-ID calculation, because `_PG_init()` calls `EnableQueryId()` and `EnableQueryId()` sets `query_id_enabled` unless `compute_query_id` is `off` [pg_stat_statements.c#EnableQueryId-call](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L398-L402) [queryjumblefuncs.c#EnableQueryId](../../../../raw/postgres-18/src/backend/nodes/queryjumblefuncs.c#L162-L173) [queryjumble.h#IsQueryIdEnabled](../../../../raw/postgres-18/src/include/nodes/queryjumble.h#L80-L111).

The entry key is `(userid, dbid, queryid, toplevel)`, so the same normalized query has separate rows for different users, databases, and top-level versus nested execution when nested tracking is enabled [pg_stat_statements.c#pgssHashKey](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L135-L153) [pg_stat_statements.c#pgss_store-key](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1318-L1327). The extension keeps a cluster-wide shared hash table capped by `pg_stat_statements.max`; when the table is full, `entry_alloc()` calls `entry_dealloc()` to discard the lowest-usage fraction and increments the global `dealloc` counter visible in `pg_stat_statements_info` [pg_stat_statements.c#pgss_memsize](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2052-L2060) [pg_stat_statements.c#entry_alloc](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2080-L2114) [pg_stat_statements.c#entry_dealloc](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2133-L2211) [pgstatstatements.sgml#pg_stat_statements_info](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L745-L797).

Representative query text is stored outside shared memory in `PG_STAT_TMP_DIR/pgss_query_texts.stat`; the shared hash entry stores only the offset, length, and encoding [pg_stat_statements.c#text-file-comment](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L15-L20) [pg_stat_statements.c#file-paths](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L79-L85) [pg_stat_statements.c#pgssEntry](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L231-L246). This is why `track_activity_query_size` does not truncate `pg_stat_statements.query`; the docs state that representative query texts are kept in an external disk file and can store very long query texts, though the file can grow large and texts may be discarded while keeping the statistics [pgstatstatements.sgml#representative-query-texts](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L719-L730) [pg_stat_statements.c#qtext_store](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2215-L2296).

If parse analysis reports constant locations, the post-parse-analysis hook creates a "sticky" entry early so it can save normalized representative text before execution finishes [pg_stat_statements.c#pgss_post_parse_analyze](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L836-L882) [pg_stat_statements.c#entry_alloc-sticky](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2063-L2114). Normalization replaces ignored constants with `$n` symbols and can squash lists of constants or external parameters into a single displayed list placeholder [pg_stat_statements.c#generate_normalized_query](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2792-L2895) [queryjumblefuncs.c#overview](../../../../raw/postgres-18/src/backend/nodes/queryjumblefuncs.c#L24-L27) [pgstatstatements.sgml#normalization](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L594-L687). PostgreSQL 18.6 builds that normalized string in an expansible `StringInfo` instead of a fixed `palloc()` sized by arithmetic that omitted the ` /*, ... */` squashed-list comment and could therefore be overrun (`8a31ffc2d4c`, CVE-2026-14676) [pg_stat_statements.c#initStringInfoExt-reserve](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2823-L2828) [release-18.sgml#CVE-2026-14676](../../../../raw/postgres-18/doc/src/sgml/release-18.sgml#L989-L1012).

The planner hook measures planning only when `pg_stat_statements.track_planning` is on, captures elapsed time plus planner buffer and WAL deltas, and stores them as `PGSS_PLAN` counters [pg_stat_statements.c#pgss_planner](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L884-L988). The executor path allocates instrumentation in `ExecutorStart`, lets `ExecutorRun` and `ExecutorFinish` execute while maintaining nesting depth, and stores execution time, rows, buffer usage, WAL usage, JIT instrumentation, and parallel-worker counts at `ExecutorEnd` [pg_stat_statements.c#executor-hooks](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L990-L1102). The utility hook measures utility commands only when `pg_stat_statements.track_utility` is on, excludes `EXECUTE` and `PREPARE`, and records utility row counts for `COPY`, `FETCH`, `CREATE TABLE AS`, `CREATE MATERIALIZED VIEW`, `REFRESH MATERIALIZED VIEW`, and `SELECT INTO` [pg_stat_statements.c#pgss_ProcessUtility](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1104-L1268).

`pgss_store()` updates counters under the entry spinlock. It increments plan or execution calls, total time, min/max/mean/stddev state, rows, shared/local/temp block counters, shared/local/temp I/O timing fields, WAL records/full-page images/bytes/WAL-buffer-full counts, JIT counters, and parallel-worker counters [pg_stat_statements.c#pgss_store-counters](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1396-L1499). `pg_stat_statements_internal()` later reads the query-text file when `showtext` is true, iterates the shared hash table, permission-filters `queryid` and `query` text, copies counters, computes population standard deviation, and emits the SQL result rows [pg_stat_statements.c#pg_stat_statements_internal](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1661-L2013).

Only superusers and roles with `pg_read_all_stats` privileges can see `queryid` and SQL text for other users' entries; other users can see the statistics but get hidden query identity/text for rows owned by other users [pg_stat_statements.c#privacy-filter](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1677-L1687) [pg_stat_statements.c#query-text-permissions](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1821-L1872) [pgstatstatements.sgml#security](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L582-L588).

## Core Settings That Directly Matter

`shared_preload_libraries` must include `pg_stat_statements` before server start. The GUC is `PGC_POSTMASTER`, the docs say it preloads libraries at server start and that changing it requires a restart, and `_PG_init()` installs no hooks unless shared-preload processing is in progress [guc_tables.c#shared_preload_libraries](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L4486-L4495) [config.sgml#shared_preload_libraries](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L11004-L11049) [pg_stat_statements.c#_PG_init-load-boundary](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L381-L396). If the SQL functions are installed but the module was not shared-preloaded, reads and resets error with `pg_stat_statements must be loaded via "shared_preload_libraries"` [pg_stat_statements.c#pg_stat_statements_internal-load-check](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1683-L1687) [pg_stat_statements.c#entry_reset-load-check](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2688-L2692).

`compute_query_id` must be `auto`, `on`, `regress`, or replaced by an external query-ID module that supplies nonzero query IDs. The GUC is `PGC_SUSET`, defaults to `auto`, and docs state that `pg_stat_statements` requires a computed query identifier [guc_tables.c#compute_query_id](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L5050-L5058) [config.sgml#compute_query_id](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8874-L8909). With `auto`, `pg_stat_statements` requests in-core IDs by calling `EnableQueryId()`; with `off`, `IsQueryIdEnabled()` returns false and statements that reach `pgss_store()` with query ID zero are skipped [queryjumble.h#IsQueryIdEnabled](../../../../raw/postgres-18/src/include/nodes/queryjumble.h#L99-L111) [pg_stat_statements.c#pgss_store-queryid](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1304-L1309).

`track_io_timing` controls whether the block-time columns can be nonzero. The GUC is `PGC_SUSET`, defaults to `off`, and its docs explicitly list `pg_stat_statements` as a consumer of database I/O timing information [guc_tables.c#track_io_timing](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L1512-L1520) [config.sgml#track_io_timing](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8745-L8777). `pg_stat_statements` itself accumulates the timing fields already present in `BufferUsage`, so `shared_blk_*_time`, `local_blk_*_time`, and `temp_blk_*_time` reflect whether the core timing counters were populated [pg_stat_statements.c#pgss_store-block-times](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1452-L1467) [pgstatstatements.sgml#io-time-columns](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L350-L409). `track_wal_io_timing` is adjacent but not a `pg_stat_statements` timing source in v18: its docs list WAL I/O timing output in `pg_stat_io` and `pg_stat_get_backend_io()`, while `pg_stat_statements` exposes WAL record/FPI/byte/buffer-full counts, not WAL I/O time columns [config.sgml#track_wal_io_timing](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8779-L8803) [pgstatstatements.sgml#wal-columns](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L412-L445).

JIT settings affect only the JIT-related columns. `pg_stat_statements` stores JIT counters only when executor state has `es_jit` instrumentation, and the view exposes function, generation, inlining, optimization, emission, deform count, and time columns [pg_stat_statements.c#ExecutorEnd-jit](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1083-L1095) [pg_stat_statements.c#pgss_store-jit](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1473-L1493) [pgstatstatements.sgml#jit-columns](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L448-L537). The relevant settings are `jit` (`PGC_USERSET`, default `on`), `jit_above_cost`, `jit_inline_above_cost`, `jit_optimize_above_cost` (`PGC_USERSET` cost thresholds, `-1` disables the respective phase), `jit_expressions`, `jit_tuple_deforming` (`PGC_USERSET` developer settings), and `jit_provider` (`PGC_POSTMASTER`, restart required) [guc_tables.c#jit](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L2023-L2032) [guc_tables.c#jit-costs](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3960-L3991) [config.sgml#jit-costs](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L6217-L6271) [config.sgml#jit](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L6559-L6573) [config.sgml#jit-expressions-deforming](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L12845-L12893) [config.sgml#jit_provider](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L11054-L11066).

Parallel-query settings affect the two parallel-worker columns by changing whether the leader plans workers and whether workers are available. `pg_stat_statements` stores `parallel_workers_to_launch` and `parallel_workers_launched` from executor state at `ExecutorEnd`, and v18 exposes both columns in the 1.12 SQL function/view [pg_stat_statements.c#ExecutorEnd-parallel-counters](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1083-L1095) [pg_stat_statements.c#pgss_store-parallel](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1495-L1497) [pg_stat_statements--1.11--1.12.sql#parallel-columns](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements--1.11--1.12.sql#L15-L76). The direct worker-capacity settings are `max_worker_processes` (`PGC_POSTMASTER`, restart), `max_parallel_workers_per_gather` (`PGC_USERSET`, default `2`, `0` disables parallel query execution for a gather), and `max_parallel_workers` (`PGC_USERSET`, capped by `max_worker_processes`) [guc_tables.c#worker-GUCs](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3341-L3350) [guc_tables.c#parallel-worker-GUCs](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3627-L3647) [config.sgml#parallel-worker-settings](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L2873-L2931) [config.sgml#max_parallel_workers](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L2987-L3004). Planner-cost settings such as `parallel_setup_cost`, `parallel_tuple_cost`, `min_parallel_table_scan_size`, and `min_parallel_index_scan_size` also affect whether a parallel plan is considered or chosen [guc_tables.c#min-parallel-scan-size](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3727-L3747) [guc_tables.c#parallel-costs](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3937-L3957) [config.sgml#parallel-cost-settings](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L6111-L6170).
