# How track_activity_query_size Is Used in PostgreSQL 18 (unverified)

## Question

Follow AGENTS.md.
In PostgreSQL 18, how is `track_activity_query_size` used?

## Short Answer

`track_activity_query_size` sets the byte size of each backend's shared-memory activity-string slot, which is the storage behind `pg_stat_activity.query` and the older `pg_stat_get_backend_activity()` function [guc_tables.c#track_activity_query_size](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3772-L3781) [system_views.sql#pg_stat_activity](../../../../raw/postgres-18/src/backend/catalog/system_views.sql#L878-L904) [pg_proc.dat#pg_stat_get_backend_activity](../../../../raw/postgres-18/src/include/catalog/pg_proc.dat#L5724-L5727). It defaults to `1024` bytes, has a minimum of `100` and a maximum of `1048576`, and is stored in the global `pgstat_track_activity_query_size` variable [guc_tables.c#track_activity_query_size](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3772-L3781) [backend_status.c#GUC-parameters](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L38-L44).

The setting is `PGC_POSTMASTER`, so changing it requires a server restart, not a reload or session change [guc_tables.c#track_activity_query_size](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3772-L3781) [config.sgml#track_activity_query_size](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8682-L8696). PostgreSQL allocates one fixed-size activity slot per backend-status slot at shared-memory startup, so larger values consume about `track_activity_query_size * (MaxBackends + NUM_AUXILIARY_PROCS)` bytes of shared activity-buffer space [backend_status.c#NumBackendStatSlots](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L27-L35) [backend_status.c#BackendStatusShmemSize](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L77-L107) [backend_status.c#BackendStatusShmemInit](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L170-L188).

## What It Sizes

Each live backend or auxiliary process has a `PgBackendStatus` entry in shared memory, and `st_activity_raw` points to its current-command string storage [backend_status.h#PgBackendStatus](../../../../raw/postgres-18/src/include/utils/backend_status.h#L86-L97) [backend_status.h#st_activity_raw](../../../../raw/postgres-18/src/include/utils/backend_status.h#L150-L158). `BackendStatusShmemSize()` includes `pgstat_track_activity_query_size * NumBackendStatSlots` for the activity buffer, where `NumBackendStatSlots` is `MaxBackends + NUM_AUXILIARY_PROCS` [backend_status.c#NumBackendStatSlots](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L27-L35) [backend_status.c#BackendStatusShmemSize](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L77-L107).

During shared-memory initialization, PostgreSQL creates `"Backend Activity Buffer"` with that total size, zeroes it, and assigns each `BackendStatusArray[i].st_activity_raw` pointer to the next `track_activity_query_size` chunk [backend_status.c#BackendStatusShmemInit](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L170-L188). When a backend initializes its status entry, it clears the activity string and forces the last byte of the slot to `\0`, using `pgstat_track_activity_query_size - 1` as the last valid index [backend_status.c#pgstat_bestart_initial](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L257-L372).

## Write Path

The main SQL simple-query path stores the incoming query text before parsing by calling `pgstat_report_activity(STATE_RUNNING, query_string)` [postgres.c#exec_simple_query](../../../../raw/postgres-18/src/backend/tcop/postgres.c#L1006-L1030). The extended-query bind path reports the prepared statement source text by calling `pgstat_report_activity(STATE_RUNNING, psrc->query_string)` [postgres.c#exec_bind_message](../../../../raw/postgres-18/src/backend/tcop/postgres.c#L1619-L1681). Other producers use the same API: autovacuum builds strings such as `autovacuum: VACUUM...` and reports them, walsender reports replication commands like SQL commands, and the `worker_spi` test background worker demonstrates extension-style calls to make worker activity visible through pgstat views [autovacuum.c#autovac_report_activity](../../../../raw/postgres-18/src/backend/postmaster/autovacuum.c#L3208-L3241) [walsender.c#exec_replication_command](../../../../raw/postgres-18/src/backend/replication/walsender.c#L2109-L2116) [worker_spi.c#pgstat_report_activity](../../../../raw/postgres-18/src/test/modules/worker_spi/worker_spi.c#L240-L259).

`pgstat_report_activity()` enforces the byte limit when it writes the string: it computes `Min(strlen(cmd_str), pgstat_track_activity_query_size - 1)`, copies that many bytes into `st_activity_raw`, writes a trailing `\0`, and records the statement start timestamp [backend_status.c#pgstat_report_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L560-L677). The stored string can end in the middle of a multibyte character, because the write side truncates by bytes for speed; the structure comment explicitly pushes correct truncation to readers via `pgstat_clip_activity()` [backend_status.h#st_activity_raw](../../../../raw/postgres-18/src/include/utils/backend_status.h#L150-L158) [backend_status.c#pgstat_report_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L614-L623).

When `track_activities` is off, `pgstat_report_activity()` stops updating the query string and performs one final transition to `STATE_DISABLED`, clearing `st_activity_raw`, `st_activity_start_timestamp`, transaction start, wait event, `query_id`, and `plan_id` [backend_status.c#track_activities-disabled](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L581-L608). `track_activities` itself is a separate superuser-settable GUC, enabled by default, that controls collection of current-command information [guc_tables.c#track_activities](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L1483-L1493) [config.sgml#track_activities](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8660-L8678).

## Idle And Last Query Behavior

The PostgreSQL 18 docs define `pg_stat_activity.query` as the currently executing query when `state = 'active'`, and as the last executed query in other states; they also state that the default query-text truncation is `1024` bytes and is changed by `track_activity_query_size` [monitoring.sgml#pg_stat_activity-query](../../../../raw/postgres-18/doc/src/sgml/monitoring.sgml#L986-L997). The implementation matches that shape: after a command finishes, the main loop reports idle states with `cmd_str = NULL`, and `pgstat_report_activity()` only overwrites `st_activity_raw` when `cmd_str != NULL` [postgres.c#idle-state-reporting](../../../../raw/postgres-18/src/backend/tcop/postgres.c#L4569-L4642) [backend_status.c#pgstat_report_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L669-L674).

`query_start` follows the same current-or-last pattern: the docs say it is the active query start time, or the last query start time when the backend is not active, and `pgstat_report_activity()` stores `st_activity_start_timestamp` only when it receives a non-null command string [monitoring.sgml#pg_stat_activity-query_start](../../../../raw/postgres-18/doc/src/sgml/monitoring.sgml#L858-L867) [backend_status.c#pgstat_report_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L669-L674).

## Read And Display Path

Readers first copy backend status into backend-local memory. `pgstat_read_current_status()` allocates a local activity buffer of `pgstat_track_activity_query_size * NumBackendStatSlots`, copies each shared `st_activity_raw` string, and advances the local pointer by `pgstat_track_activity_query_size` for each valid entry [backend_status.c#pgstat_read_current_status](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L820-L973). `pg_stat_get_activity()` then uses `pgstat_clip_activity()` before returning the `query` column to callers with permission [pgstatfuncs.c#pg_stat_get_activity](../../../../raw/postgres-18/src/backend/utils/adt/pgstatfuncs.c#L327-L424).

`pg_stat_activity` is a SQL view over `pg_stat_get_activity(NULL)`, and its `query` column is `S.query` from that set-returning function [system_views.sql#pg_stat_activity](../../../../raw/postgres-18/src/backend/catalog/system_views.sql#L878-L904). The catalog data for `pg_stat_get_activity` includes `query` in the output argument list, and the older `pg_stat_get_backend_activity(integer)` SQL function maps to the same C-side activity reader [pg_proc.dat#pg_stat_get_activity](../../../../raw/postgres-18/src/include/catalog/pg_proc.dat#L5631-L5643) [pg_proc.dat#pg_stat_get_backend_activity](../../../../raw/postgres-18/src/include/catalog/pg_proc.dat#L5724-L5727).

`pgstat_clip_activity()` copies at most `pgstat_track_activity_query_size - 1` bytes from the raw string, then uses `pg_mbcliplen()` to remove any incomplete trailing multibyte character before returning display text [backend_status.c#pgstat_clip_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L1306-L1348). The PostgreSQL 18 release notes mention the same multibyte edge for `pg_stat_get_backend_activity()`: the shared activity string can end with an incomplete multibyte character, and readers are supposed to truncate it away [release-18.sgml#pg_stat_get_backend_activity-multibyte](../../../../raw/postgres-18/doc/src/sgml/release-18.sgml#L6592-L6603).

Activity text is permission-filtered. `HAS_PGSTAT_PERMISSIONS` allows callers with `pg_read_all_stats` privileges or privileges of the reported role, and `pg_stat_get_activity()` returns `"<insufficient privilege>"` for `query` when the caller lacks that permission [pgstatfuncs.c#HAS_PGSTAT_PERMISSIONS](../../../../raw/postgres-18/src/backend/utils/adt/pgstatfuncs.c#L20-L37) [pgstatfuncs.c#insufficient-privilege](../../../../raw/postgres-18/src/backend/utils/adt/pgstatfuncs.c#L648-L676). The docs describe the same visibility rule for current-command information [config.sgml#track_activities](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8668-L8675).

## Error And Logging Paths

Deadlock reporting uses the same activity buffer. `DeadLockReport()` appends each deadlocked process's current activity by calling `pgstat_get_backend_current_activity(info->pid, false)`, and that reader returns a clipped activity string or special messages such as `"<command string not enabled>"` [deadlock.c#DeadLockReport](../../../../raw/postgres-18/src/backend/storage/lmgr/deadlock.c#L1120-L1138) [backend_status.c#pgstat_get_backend_current_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L976-L1055).

Postmaster crash logging also uses the activity buffer. On a nonzero child exit status, `LogChildExit()` asks `pgstat_get_crashed_backend_activity()` for the failed process's activity and includes it as `Failed process was running: ...` when a string is available [postmaster.c#LogChildExit](../../../../raw/postgres-18/src/backend/postmaster/postmaster.c#L2798-L2844). The crash reader validates that the raw activity pointer falls inside the backend activity buffer using `pgstat_track_activity_query_size`, then copies only ASCII-safe characters up to `Min(buflen, pgstat_track_activity_query_size)` [backend_status.c#pgstat_get_crashed_backend_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L1057-L1130). `LogChildExit()` passes a fixed 1024-byte local buffer, so crash-log detail is also constrained by that local buffer even if the GUC is larger [postmaster.c#LogChildExit](../../../../raw/postgres-18/src/backend/postmaster/postmaster.c#L2798-L2811).

## Operational Consequences

Increase `track_activity_query_size` when monitoring needs more of long query strings in `pg_stat_activity.query`, deadlock reports, or crash details; the setting does not make `track_activities` collect anything when `track_activities` is disabled [monitoring.sgml#pg_stat_activity-query](../../../../raw/postgres-18/doc/src/sgml/monitoring.sgml#L986-L997) [backend_status.c#track_activities-disabled](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L581-L608). Because it is `PGC_POSTMASTER`, set it in server configuration before restart; `postgresql.conf.sample` shows the default value and labels the change as requiring restart [guc_tables.c#track_activity_query_size](../../../../raw/postgres-18/src/backend/utils/misc/guc_tables.c#L3772-L3781) [postgresql.conf.sample#track_activity_query_size](../../../../raw/postgres-18/src/backend/utils/misc/postgresql.conf.sample#L658-L662).

The cost of increasing it is shared memory at startup plus local snapshot memory for readers of backend status. The shared path reserves `pgstat_track_activity_query_size * NumBackendStatSlots`, and the snapshot path allocates the same per-slot activity size with `MemoryContextAllocHuge()` because large settings and many connections can exceed 1GB [backend_status.c#BackendStatusShmemSize](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L77-L107) [backend_status.c#pgstat_read_current_status](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L841-L861).

## Impact On pg_stat_statements

`track_activity_query_size` does not size or truncate `pg_stat_statements.query`. `pg_stat_statements` stores representative query strings in its own temporary external query-text file, keeping offsets in shared memory specifically to avoid using shared memory for query text and to avoid truncating oversized query strings [pg_stat_statements.c#query-text-storage-comment](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L15-L20) [pg_stat_statements.c#PGSS_TEXT_FILE](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L79-L85). Its documentation says representative query texts are kept in an external disk file, do not consume shared memory, and can store very lengthy query texts, though the file can grow large and query texts can be discarded while preserving the `queryid` statistics [pgstatstatements.sgml#representative-query-texts](../../../../raw/postgres-18/doc/src/sgml/pgstatstatements.sgml#L720-L730).

The data path is separate from `pg_stat_activity.query`: `pg_stat_statements` hooks receive the parser/planner/executor source text (`p_sourcetext`, `query_string`, or `sourceText`) and pass that text to `pgss_store()` [pg_stat_statements.c#pgss_post_parse_analyze](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L861-L875) [pg_stat_statements.c#pgss_planner](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L888-L955) [pg_stat_statements.c#pgss_ExecutorEnd](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1069-L1092). `pgss_store()` then cleans the relevant source-text slice, uses `(userid, dbid, queryid, toplevel)` as the hash key, and writes the representative text with `qtext_store()` when it creates a new entry [pg_stat_statements.c#pgss_store](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1281-L1394) [pg_stat_statements.c#qtext_store](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L2230-L2279).

The overlap is `query_id`, not the text-size GUC. When loaded from `shared_preload_libraries`, `pg_stat_statements` calls `EnableQueryId()` so query identifier calculation is enabled when `compute_query_id` is `auto`; `pgss_store()` returns without storing anything when the query ID is zero [pg_stat_statements.c#_PG_init](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L381-L418) [pg_stat_statements.c#pgss_store-queryid](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1304-L1309). PostgreSQL also exposes the current backend's query ID in `pg_stat_activity.query_id`, and the `pg_stat_statements` extended-protocol regression test checks that an execute message sets that field [system_views.sql#pg_stat_activity](../../../../raw/postgres-18/src/backend/catalog/system_views.sql#L878-L904) [extended.sql#query_id_set](../../../../raw/postgres-18/contrib/pg_stat_statements/sql/extended.sql#L1-L8). Changing `track_activity_query_size` can make `pg_stat_activity.query` show more or less text, but it does not change `pg_stat_activity.query_id`, `pg_stat_statements.queryid`, the `pg_stat_statements` hash key, or the extension's representative query-text file path [backend_status.c#pgstat_report_activity](../../../../raw/postgres-18/src/backend/utils/activity/backend_status.c#L614-L674) [pg_stat_statements.c#pgss_store](../../../../raw/postgres-18/contrib/pg_stat_statements/pg_stat_statements.c#L1318-L1327).

## Tests And Documentation

The same-checkout documentation for the GUC states its purpose, units, default, and server-start-only scope [config.sgml#track_activity_query_size](../../../../raw/postgres-18/doc/src/sgml/config.sgml#L8682-L8696). The `pg_stat_activity` documentation states that `query` shows current or last query text and is truncated at 1024 bytes by default, with `track_activity_query_size` changing that value [monitoring.sgml#pg_stat_activity-query](../../../../raw/postgres-18/doc/src/sgml/monitoring.sgml#L986-L997).

The same-checkout regression GUC test covers the related `track_activities` behavior that disabling it disables `query_id` reporting in `pg_stat_activity`, but it does not exercise a non-default `track_activity_query_size` value [guc.sql#track_activities](../../../../raw/postgres-18/src/test/regress/sql/guc.sql#L325-L335). The `pg_stat_statements` regression suite has an adjacent extended-protocol test that reads `pg_stat_activity.query_id`, but the only `pg_stat_activity` reference in `contrib/pg_stat_statements` is that query-ID test, not a dependency on activity query text length [extended.sql#query_id_set](../../../../raw/postgres-18/contrib/pg_stat_statements/sql/extended.sql#L1-L8). No dedicated regression or TAP test named `track_activity_query_size` was found during this pass; the source paths above are the evidence for allocation, truncation, display, deadlock, crash-log, and `pg_stat_statements` non-impact behavior.
